# 课程写作规范

## 适用范围

本规范适用于 `course/` 下的全部 38 节课程。每个文件只讲一个阶段，使用简体中文，并在第一次出现专业术语时给出通俗解释。

## 固定栏目

每节课程必须按以下顺序包含全部 20 个三级标题；标题文字不得改写，以便 `node scripts/audit-course.mjs` 自动检查。

1. `### 本课目标`
2. `### 你将完成`
3. `### 前置条件`
4. `### 核心概念`
5. `### 本课范围`
6. `### 关键决策`
7. `### 操作前检查`
8. `### 步骤 1`
9. `### 步骤 2`
10. `### 步骤 3`
11. `### 步骤 4`
12. `### 常见问题`
13. `### 安全与合规`
14. `### Codex 提示词`
15. `### 产出物`
16. `### 验收标准`
17. `### 自查清单`
18. `### 提交记录`
19. `### 延伸阅读`
20. `### 下一课预告`

## 编写要求

- 课程 `00`–`35` 是完整基础课：每节不少于 1,500 个 UTF-16 代码单元，包含可执行、可观察的操作步骤与 `### 步骤 1`。
- 课程 `36`–`37` 是结构化骨架：也必须保留全部固定栏目，并写明本阶段目标、前置条件、产出物、验收标准和下一课依赖。
- 开发类课程的 `### Codex 提示词` 必须包含：角色、任务、上下文、允许范围、禁止范围、功能要求、安全要求、测试要求、验收要求和报告要求。
- 使用占位符，例如 `<你的 AppID>`、`<环境变量名称>`；不得写入真实凭据、个人信息或证书内容。
- 微信规则、费用、认证、备案、支付、审核、发布等可能变化的信息不得编造固定结论，并标注：`执行时请以微信公众平台当前页面和官方文档为准。`
- 教程步骤应写清操作位置、输入内容、预期结果和失败时的检查点；避免只给理论解释。

## 最小提示词模板

```text
角色：你是资深微信小程序与微信云开发工程师。
任务：完成【本课明确任务】。
上下文：项目为同城线下一对一健身私教预约平台。
允许范围：【允许修改的文件或文档】。
禁止范围：不修改订单状态机；不接触真实凭据；不新增未要求的功能。
功能要求：【可验证功能】。
安全要求：金额使用整数分；敏感操作仅通过后端；不输出密钥或个人数据。
测试要求：【最小检查命令或手工步骤】。
验收要求：【可观察结果】。
报告要求：列出修改文件、验证结果、遗留风险和下一步。
```
