# 第 21 阶段：私教端小程序开发

### 本课目标

围绕已审核教练的最小工作流设计私教端：维护公开资料与可约时段、查看归属订单、确认服务、核销完课，并安全查看收益摘要。

### 你将完成

私教端页面清单、页面与后端动作映射、权限边界、加载/空态/错误态和虚构数据验收记录。

### 前置条件

- 已完成教练入驻、场馆关联、排期与订单状态机。
- 已确认私教端只有审核通过的教练可进入服务管理功能。
- 已有 `schedule.manage`、`order.transition`、`checkin.verify` 等受控接口契约。

### 核心概念

私教端不是管理员后台。它只能读取和操作“当前已审核教练本人”的公开资料、有效场馆关联、排期、归属订单和本人收益摘要；不能查询全平台用户、审核材料、其他教练订单、支付原文、退款内部信息或全量钱包流水。

每个动作都映射到具名后端请求：修改时段调用排期接口，确认订单调用状态转换接口，核销调用核销接口。页面根据后端返回的当前状态刷新，不能把按钮点击或本地缓存当作订单已确认、已核销或收益已结算。

### 本课范围

本课覆盖私教端 MVP 页面和验收，不做即时聊天、客户画像、复杂营销、提现打款、自动排班或前端直连数据库。收益完整结算和提现在第 27 课处理。

### 关键决策

- 未申请/待审/驳回教练看到申请进度和必要的下一步；只有审核通过且具备公开服务条件才看到排期和订单操作。
- 排期只显示本人有效场馆关联，创建、停用和冲突由后端校验；已锁定/已约时段不提供直接删除入口。
- 订单仅按 `coach_id` 读取本人范围，按钮严格按状态机和服务时间显示。
- 收益首页只展示经后端计算的摘要金额分和状态，不展示支付凭据或可编辑余额。

### 操作前检查

1. 对照 `docs/ORDER_STATE.md` 列出教练可执行状态动作与不可执行状态。
2. 对照 `docs/DATA_MODEL.md` 确认页面不读取 `coach_certificates`、`payments`、`refunds` 的敏感原文。
3. 准备已审核教练、待审教练、有效场馆、未来时段和不同订单状态的虚构数据。
4. 为每个页面定义加载、空态、权限拒绝和重试提示。

### 步骤 1

设计身份与资料入口。启动时调用受控身份接口，依据后端返回的申请/审核/上架摘要选择页面：待审只显示进度，驳回显示脱敏可操作原因，审核通过展示资料、场馆和排期入口。资料编辑只提交允许展示字段，不能编辑审核状态、角色、主键或余额。

预期结果是普通用户伪造教练角色不会看到管理数据；教练资料变更需重新走必要审核时，页面显示待生效而不是立即向用户端宣称已上线。

### 步骤 2

设计排期页：按日期展示本人未来时段和状态，创建时只能选择有效关联场馆与合法时间；保存后等待后端响应刷新。相交、过去时间、失效场馆或已锁定时段的操作显示稳定错误提示，不通过前端隐藏来规避。

用户预约造成 `HELD/BOOKED` 后，教练端只展示状态和相关订单摘要。请假或下架请求由后端判断在途订单；页面不能批量把已约时段改为不可约。

### 步骤 3

设计订单与核销页。订单列表按待确认、待服务、进行中、已完成等合法状态聚合；详情只展示本次履约所需的用户昵称/联系边界、项目场馆快照和服务时间。确认、开始服务、完课均向后端发具名动作并带幂等键。

核销页要求订单状态、教练归属和服务窗口全部由后端校验；扫描/输入的核销信息只是候选输入。重复核销、跨教练核销、过早核销或已退款订单都应被拒绝且不改变状态。

### 步骤 4

使用虚构数据走读：待审教练被限制；已审核教练创建时段；相交时段被拒绝；本人确认订单成功；他人订单无法读取；重复核销被拒绝；收益摘要刷新以服务端为准。预期每项均没有前端直写敏感集合。

在开发者工具/真机中检查网络中断、登录过期、空订单和重复点击。真实支付、真实收益、提现和证书材料不作为本课测试数据。

### 常见问题

- **前端传教练 ID 查询订单：** 后端从可信身份确定教练归属，客户端 ID 只能被校验。
- **已约时段仍可删除：** 应让后端按时段/订单状态拒绝或引导走受控取消流程。
- **核销后页面直接显示完课：** 核销、开始服务、完课是不同状态，必须等待后端返回。
- **收益摘要等于可提现余额：** 摘要、冻结、结算和提现状态不同，不能在页面混用。
- **待审教练能编辑公开上线状态：** 审核与上架只能由后台/后端处理。

### 安全与合规

教练端遵循最小可见原则：只显示本人履约必需资料，敏感个人信息、证书、支付、退款和后台备注不进入页面或日志。排期、订单、核销、收益和提现相关写入均由后端鉴权、状态和幂等校验。执行时请以微信公众平台当前页面和官方文档为准。

### Codex 提示词

```text
角色：你是资深微信小程序前端、预约履约与权限安全工程师，严格遵守项目根目录 AGENTS.md。

任务：在既有架构和视觉规范内完成私教端 MVP：审核状态、资料、场馆排期、本人订单、确认/核销和收益摘要。

上下文：教练必须审核通过后才管理服务；订单状态、排期、核销、收益均由云函数控制，客户端不可信。

允许范围：仅修改私教端页面、组件、状态、必要共享类型和明确需要的文档/测试；复用现有接口与样式。

禁止范围：不得读取他人订单/材料、直写订单/排期/收益、接入真实支付/提现、重构无关 UI；不得输出真实个人数据、凭据或生产配置。

功能要求：提供审核状态分流、排期管理、订单状态动作、核销和收益摘要；每个页面具备加载、空态、错误与重试；按钮由后端状态驱动。

安全要求：从可信身份确定教练归属；最小展示用户资料；不暴露支付、证书、后台备注；敏感动作由后端校验并记录脱敏日志。

测试要求：用虚构数据验证待审限制、创建/冲突排期、本人订单、越权订单拒绝、核销幂等、登录过期和网络失败；说明预期结果。

验收要求：教练只操作授权范围数据；不出现前端敏感直写；状态刷新以服务端为准；无秘密、真实数据或未说明的假接口。

报告要求：列出修改文件、页面/权限决策、验证结果、未执行项、风险和下一步；附 git diff 摘要，不要自行提交。
```

### 验收标准

- [ ] 仅审核通过的教练进入服务管理，待审/驳回状态有安全反馈。
- [ ] 排期和订单只归属本人，越权读取/写入被后端拒绝。
- [ ] 订单确认、核销、完课和收益展示遵循状态机与后端响应。
- [ ] 每页处理加载、空态、登录失效、网络失败和重复点击。
- [ ] 未展示证书、支付、退款、后台备注或真实敏感数据。

### 自查清单

- [ ] 没有使用客户端角色、金额或订单状态作为可信判断。
- [ ] 已约/锁定时段没有直接删除路径。
- [ ] 重复核销和越权核销无状态副作用。
- [ ] 收益摘要不允许前端编辑或作为提现结论。
- [ ] 已检查日志、请求样例和 git diff 的脱敏。
