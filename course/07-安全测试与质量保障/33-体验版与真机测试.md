# 第 33 阶段：体验版与真机测试

### 本课目标

建立体验版与真机验证流程，覆盖开发者工具无法替代的登录、授权、弱网、设备兼容、订阅消息、定位、支付调起前置和回归证据。

### 你将完成

测试成员/版本管理边界、真机测试清单、问题记录模板、回归与发布阻断规则。

### 前置条件

- 自动化测试与跨端联调已通过，阻断/高缺陷已关闭或明确阻断。
- 已有隔离测试环境、测试成员和虚构测试数据。
- 平台体验版、成员管理、真机调试和审核入口已由有权限人员在当前官方页面核实。

### 核心概念

体验版验证真实小程序运行环境，不能被模拟器完全替代：登录状态、授权弹窗、系统设置、网络切换、机型尺寸、性能、定位、通知、支付调起和平台限制都可能不同。体验版仍不是生产版本，测试成员、环境和数据都要受控。

真机证据应可追溯但不泄露数据：记录版本号、设备/系统范围、环境别名、步骤、预期、实际、截图/录屏位置和脱敏请求 ID；不保存真实用户、支付、位置、证书或凭据。

### 本课范围

本课组织测试与记录，不进行正式发布、不使用真实支付/提现、不导入生产用户或绕过平台成员权限。平台实际可测能力、审核限制和成员规则以当前官方页面为准。

### 关键决策

- 体验版只连接指定测试环境，显著标识测试数据与模拟支付，禁止连接生产敏感配置。
- 测试成员最小化、定期移除；测试账号与角色隔离，管理员账号不用于普通用户流程。
- 用例覆盖成功/拒绝/失败/恢复：登录、授权、网络、定位、订单、通知、支付调起前置、隐私、页面兼容。
- 问题按阻断/高/中/低分级，修复必须回归主流程和相关异常；无证据不宣称通过。

### 操作前检查

1. 记录测试版本、提交摘要、环境别名和负责人员，不记录真实 AppID/环境 ID/凭据。
2. 确认测试环境无生产支付、商户、钱包或个人资料，模拟支付标识可见。
3. 准备至少两类设备/系统和网络状态：正常、弱网/断网、授权拒绝/系统关闭。
4. 从测试计划选择主流程、退款/超时、越权、定位降级和消息失败回归用例。

### 步骤 1

配置体验版和测试成员。仅邀请必要成员，按测试角色分配虚构账号；发布前核对版本指向测试环境、错误日志脱敏、调试开关关闭或受控。若环境/成员入口与课程不同，停止猜测，执行时请以微信公众平台当前页面和官方文档为准。

安装后先验证启动、登录、退出/重新登录和角色隔离。预期：测试用户只见自身订单，教练只见本人服务，管理员入口由后端角色控制；无真实数据或生产环境出现。

### 步骤 2

执行授权与系统能力用例：拒绝/再次授权用户资料、定位、订阅消息；手动选城降级；系统关闭定位/通知后的提示；网络断开和恢复；前后台切换；不同屏幕尺寸。预期：拒绝可选权限不阻断浏览/预约，弱网不重复创建订单，错误提示可重试且不泄露内部信息。

对支付仅验证真实接入前置和安全调起流程，或使用模拟支付；未经授权不得发起真实扣款。支付返回/中断后刷新订单，以后端状态为准。

### 步骤 3

执行业务回归：浏览、场馆/时段选择、创建预约、冲突、模拟支付、教练确认、核销、完课、评价、退款申请、后台审计摘要。每个动作核对真机页面与后端状态/日志一致；重复点击、应用杀后台、网络超时后重新进入仍需幂等。

记录性能和兼容观察：首屏、列表空态、错误页、长文本、授权弹窗、页面返回和无障碍基本可操作性。发现崩溃、卡死、资金/权限/状态异常立即标为阻断，停止继续发布。

### 步骤 4

提交问题单：版本、设备/系统、网络、角色、虚构数据代号、复现步骤、预期/实际、严重级别、脱敏证据、负责人、修复提交和回归结果。将未在真机验证的项目（真实支付、真实通知模板、生产地图等）列为上线前待办。

体验版退出条件：主流程和关键异常在目标设备范围通过，阻断/高问题关闭，隐私/权限/弱网证据齐全，剩余风险被负责人接受。不要将“能安装”视为“可发布”。

### 常见问题

- **模拟器通过就跳过真机：** 授权、网络和平台差异仍可能失败。
- **测试版连到生产环境：** 可能污染用户/资金，必须环境隔离。
- **用真实账号截图：** 使用虚构数据并脱敏证据。
- **弱网重试创建多订单：** 以幂等键和订单列表刷新确认结果。
- **只测成功授权：** 必测拒绝、系统关闭、恢复和降级。

### 安全与合规

体验版测试成员、环境和数据最小化；不得使用真实个人信息、支付、银行卡、凭据、证书、位置或生产配置。真机日志、录屏、截图和缺陷单脱敏；关键状态由后端事实决定。执行时请以微信公众平台当前页面和官方文档为准。

```text

任务：制定并执行体验版/真机测试清单、问题记录和回归门禁，覆盖授权、弱网、跨端状态和设备差异。

上下文：自动化和联调已完成；体验版仅使用虚构数据与测试环境，真实支付和生产发布不在本课执行。

允许范围：仅修改测试清单、体验版配置记录、必要的测试/修复文件、课程与 docs/TEST_PLAN.md、docs/RELEASE_CHECKLIST.md。

禁止范围：不得连接生产数据、使用真实支付/凭据/个人资料、绕过成员管理、跳过阻断问题或重构无关功能。

功能要求：版本/成员/环境管理；登录、授权拒绝、定位降级、弱网、前后台、设备兼容、订单回归、模拟支付和问题分级回归。

安全要求：最小测试成员和数据，真机证据脱敏，状态以后端为准，真实平台能力遵循当前官方要求。

测试要求：每项记录设备/网络/角色/步骤/预期/实际/证据/缺陷；覆盖正常、拒绝、失败、恢复和重复操作。

验收要求：主路径和关键异常有真机证据；阻断/高问题关闭；未覆盖第三方/生产项透明记录；无秘密或真实数据。

报告要求：列出修改文件、设备覆盖、用例结果、缺陷与回归、剩余风险和下一步；附 git diff 摘要，不要自行提交。
```

### 产出物

- 体验版环境、成员和版本清单。
- 真机功能/授权/弱网/兼容测试记录。
- 缺陷分级、回归和发布阻断规则。

### 验收标准

- [ ] 体验版仅使用隔离环境、虚构数据和最小测试成员。
- [ ] 登录、角色、授权拒绝、定位降级、弱网、前后台和订单回归有真机证据。
- [ ] 支付仅按授权验证前置/模拟路径，未执行未授权真实扣款。
- [ ] 缺陷可复现、分级、修复和回归；阻断/高问题不放行。
- [ ] 证据、日志和问题单无真实凭据、个人资料或生产配置。

### 自查清单

- [ ] 未把开发者工具结果替代真机结果。
- [ ] 测试成员和环境均最小化、可撤销。
- [ ] 已测权限拒绝、网络恢复和重复操作。
- [ ] 已从后端确认订单/支付状态，而非只看页面。
- [ ] 已列出未覆盖的生产能力和上线待办。
