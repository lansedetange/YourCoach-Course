# 第 30 阶段：权限、隐私与安全

### 本课目标

将课程中已确定的安全边界汇总为可执行基线：资产清单、角色授权、数据最小化、输入校验、密钥管理、日志脱敏、依赖治理和安全验证证据。

### 你将完成

`docs/SECURITY.md` 安全基线、三端/后端权限检查表、隐私数据清单和最小安全验证记录。

### 前置条件

- 已完成数据模型、接口、订单、支付、履约、通知和位置设计。
- 已区分用户、教练、管理员、系统回调四类调用方。
- 已确认本课输出是工程安全基线，不替代法律意见、平台审核或第三方渗透测试。

### 核心概念

安全从信任边界开始：所有客户端输入、页面角色、金额、订单状态、位置、支付结果和外部回调都是不可信的，必须在后端验证身份、权限、归属、类型、范围、状态、幂等和审计。数据库权限、云函数校验、状态机和前端隐藏缺一不可，且各自不能替代。

隐私遵循最小必要：先说明目的，再收集最少字段；公开资料、本人资料、审核材料、支付/账务资料分离；位置、证书、联系方式、支付信息和日志遵循最小展示、最短保留、最小访问和受控删除/导出流程。

### 本课范围

本课建立可验收的工程清单，不实施攻防演练、购买安全服务、完整合规认证或固定法规结论。发现高风险问题必须停止上线并由责任人处理，不用课程文本掩盖风险。

### 关键决策

- 授权由后端可信身份与对象归属决定；客户端角色、用户 ID、金额、状态均不可信。
- 敏感集合默认拒绝前端写入；订单、支付、退款、核销、钱包、提现和审核只由云函数受控处理。
- 凭据仅由受控密钥管理/环境变量注入，永不进入仓库、日志、截图、前端包或提示词。
- 安全事件和业务审计只记录必要脱敏摘要、请求 ID 和结果；高风险动作有原因、二次确认和不可变审计。

### 操作前检查

1. 读取 `docs/DATA_MODEL.md`、`docs/API.md`、`docs/ORDER_STATE.md`，列出资产和信任边界。
2. 检查仓库、示例、日志和配置模板只使用占位符，无真实 AppID、密钥、证书、个人资料或交易。
3. 为用户、教练、管理员、系统回调列出允许读取、允许动作和拒绝路径。
4. 准备虚构越权、字段超限、金额篡改、重复请求、回调伪造和日志脱敏案例。

### 步骤 1

建立资产/控制表：订单和排期防越权/并发；支付和退款防伪造/重复记账；用户/证书/位置防过度收集与公开；钱包和提现防超额/篡改；管理员防权限扩大；配置防密钥泄露。每项指定控制：后端鉴权、状态机、事务/唯一约束、字段白名单、最小数据库规则、密钥注入、审计与告警。

将剩余风险和负责人写入 `docs/SECURITY.md`。安全项没有证据不标记完成；不确定平台规则原样标记为人工核实。

### 步骤 2

逐接口执行输入与授权审查。所有写接口校验调用者、对象归属、字段类型/长度/枚举、金额整数分、当前状态、时间窗口和幂等键；管理员接口额外校验角色、理由、影响范围和审计。读取接口按公开/本人/受控后台分层，不用“能猜到 ID”作为访问条件。

数据库规则采用默认拒绝和最小读写，云函数仍重新验证业务规则。前端只做体验性校验，不能承担权限或资金安全责任。

### 步骤 3

执行隐私与密钥检查：每个收集字段有目的、可见角色、保留/删除/导出边界；可选头像、位置、通知授权可拒绝；证书、支付、提现和审核资料不公开。扫描版本库和构建产物中的高风险模式，发现疑似凭据立即停止展示/提交、轮换和排查，不将其复制进课程。

日志只保留脱敏错误分类、请求 ID、对象摘要和结果；不记录令牌、签名、回调原文、完整身份标识、精确位置或银行卡资料。依赖升级、第三方 SDK 权限和环境访问也纳入上线检查。

### 步骤 4

用虚构数据完成安全走查：普通用户读他人订单被拒绝；教练改他人排期被拒绝；客户端篡改金额/状态被忽略或拒绝；重复回调不重复记账；未授权定位有手动降级；日志中不出现敏感样例；管理员高风险动作有审计。记录命令、结果、风险和修复责任。

将未通过的高风险项列为上线阻断，不以“后续优化”放行。执行时请以微信公众平台当前页面和官方文档为准。

### 常见问题

- **只做前端权限判断：** 直接调用接口仍可绕过，后端必须鉴权。
- **数据库有规则就不校验云函数：** 规则不表达完整业务状态和金额逻辑。
- **开发日志可先打印全部数据：** 开发数据也会扩散，始终脱敏。
- **把密钥放示例方便同学：** 使用占位符和受控注入；泄露后按事故处理。
- **隐私告知存在就收集任何字段：** 仍需最小必要与可拒绝。

### 安全与合规

不在课程、代码、日志、截图、示例或版本库写入真实个人资料、AppID、商户资料、密钥、证书、令牌、交易或生产配置。敏感状态由后端最小权限、状态机、幂等和审计保护；安全/隐私相关平台规则和法律要求须按当前官方信息和专业意见执行。执行时请以微信公众平台当前页面和官方文档为准。

### Codex 提示词

```text
角色：你是资深应用安全、隐私工程与微信云开发审计工程师，严格遵守项目根目录 AGENTS.md。

任务：审查并完善 YourCoach 的安全基线、权限矩阵、数据最小化、密钥/日志规则和可运行验证证据。

上下文：平台有用户、教练、后台和云函数；订单、支付、退款、核销、钱包、位置、通知均是敏感边界。

允许范围：仅修改安全相关文档、最小必要的后端校验/测试和课程；使用虚构脱敏样例。

禁止范围：不得降低权限、使用真实凭据/个人资料、修改生产环境、输出攻击步骤或无关重构。

功能要求：资产与风险表、后端授权/输入校验、最小数据库规则、隐私字段边界、密钥管理、日志脱敏、审计和上线阻断项。

安全要求：默认拒绝、可信身份、对象归属、整数分、状态机、幂等、事务、最小展示、凭据不入库和不可变审计。

测试要求：验证越权读取/写入、金额/状态篡改、重复请求、回调伪造、位置拒绝和日志脱敏；说明预期拒绝或无副作用。

验收要求：敏感操作均经后端，隐私最小化可追溯，发现高风险项可阻断上线，无秘密或真实数据泄露。

报告要求：列出修改文件、风险/控制/证据、验证结果、未修复风险与负责人、下一步；附 git diff 摘要，不要自行提交。
```

### 产出物

- 安全资产、风险、控制和验证证据表。
- 权限/隐私/密钥/日志检查清单。
- 六类虚构安全验证记录和上线阻断项。

### 验收标准

- [ ] 每类敏感资产有明确风险、控制、负责人和验证方式。
- [ ] 三端和回调均由后端进行身份、归属、输入、状态、金额和幂等校验。
- [ ] 个人数据、位置、证书、支付与日志遵循最小化和访问分层。
- [ ] 凭据不进入仓库/日志/前端，安全事件可审计。
- [ ] 高风险未解决项被标记为上线阻断。

### 自查清单

- [ ] 未把前端、数据库单一规则或隐藏按钮当作完整安全控制。
- [ ] 未提交真实密钥、个人数据、交易或生产配置。
- [ ] 已为每个高风险写操作记录拒绝/审计路径。
- [ ] 已验证日志和错误信息脱敏。
- [ ] 已标注需按当前平台规则人工复核的项目。
