# 第 10 阶段：创建项目工程

### 本课目标

创建一个只表达职责边界的单仓库工程，使用户端、教练端、后台、云函数和共享代码不会互相混放。

### 你将完成

1. 一份与课程一致的工程目录。
2. 根目录 README 中的启动入口说明。
3. 不含订单、支付或真实配置的最小工程检查记录。

### 前置条件

1. 已完成第 09 课，能创建分支、查看 diff、只提交指定文件。
2. 已完成第 06–08 课的范围、流程与页面地图。
3. 已打开微信开发者工具和终端；本课不需要真实 AppID。

### 核心概念

- **单仓库（monorepo）**：一个 Git 仓库中管理多个相关应用和共享包。
- **应用边界**：用户端、教练端、后台各自拥有页面和运行配置，不能直接互相引用页面文件。
- **共享包**：只放跨端复用的类型、常量和纯工具；不放登录态、数据库连接或支付密钥。

### 本课范围

只创建目录、说明文件和空工程配置。不要为“让它跑起来”提前实现登录、数据库、排期、订单、支付、云函数或 UI；这些在后续课完成。

### 关键决策

采用以下最小目录，而不是为每个未来功能新建服务：

```text
yourcoach-course/
├── apps/user-miniprogram/     # 用户端
├── apps/coach-miniprogram/    # 私教端
├── apps/admin-web/            # PC 管理后台
├── cloudfunctions/api/        # 后端入口，敏感动作在此实现
├── packages/shared-types/     # 跨端类型
├── packages/shared-constants/ # 状态和值域常量
├── packages/shared-utils/     # 无副作用工具
├── docs/ scripts/ tests/
└── README.md AGENTS.md
```

### 操作前检查

1. 在仓库根目录运行 `git status -sb`，确认没有未知改动。
2. 阅读 `docs/PRODUCT.md`、`docs/SPEC.md` 和 `AGENTS.md`。
3. 创建名为 `codex/project-scaffold` 的分支或使用团队约定分支；不要直接混入无关任务。

### 步骤 1

创建目录和职责说明。

1. 在仓库根目录创建上图中的 `apps/`、`cloudfunctions/`、`packages/`、`tests/` 目录。
2. 在每个应用目录放置简短 README，写明端角色、启动命令位置和“不得放入”的内容。
3. 在 `cloudfunctions/api/README.md` 写明：订单、支付、退款、核销和收益状态由后端处理。
4. 预期结果：任何新文件都有唯一归属；用户端页面不会放进教练端目录。

### 步骤 2

建立最小配置边界。

1. 用户端和教练端分别在微信开发者工具创建空白练习工程，项目目录选择各自的 `apps/` 子目录。
2. 后台只初始化 TypeScript/Next.js 工程骨架；不接入数据库、登录或支付。
3. 共享包只导出占位类型，例如 `OrderStatus` 的声明位置，不定义业务流转。
4. 所有 AppID、云环境 ID 和密钥使用 `<PLACEHOLDER>`，真实值只在本机受控配置中保存。
5. 预期结果：三个端能被独立识别，任何一个端的失败不会要求复制另一个端的配置。

### 步骤 3

验证目录和入口。

1. 在根目录运行：

```bash
find apps cloudfunctions packages -maxdepth 2 -type d
git diff --stat
```

2. 分别在微信开发者工具打开两个小程序目录；后台的启动命令必须在 `apps/admin-web/README.md` 中说明，并记录预期结果。
3. 失败时先检查目录是否选错、README 是否说明依赖和终端位置；不要安装未知全局依赖。
4. 预期结果：目录职责清楚，空工程可打开或能明确报告缺少的正式初始化步骤。

### 步骤 4

审阅和提交工程边界。

1. 运行 `git diff --check`，确认没有 `.env`、证书、构建缓存或真实项目配置。
2. 使用本课 Codex 提示词只审阅目录职责，不让它生成业务页面。
3. 提交前运行 `node scripts/audit-course.mjs` 和项目各自的最小检查。
4. 预期结果：提交只包含工程边界和文档，后续课程可在固定目录中递增实现。

### 常见问题

- **把所有代码放在一个小程序目录**：教练端和用户端权限、页面、发布 AppID 不同，应隔离。
- **共享包引用云函数或 wx API**：会使后台无法复用。共享包保持纯类型、常量和工具。
- **为了启动复制真实配置**：用占位符和本地受控配置；先验证目录，不验证生产资源。
- **提前写订单服务**：第 19 课状态机未定，提前实现会返工。

### 安全与合规

仓库不提交 AppID、云环境 ID、密钥、证书、手机号、生产日志或 `.env`。前端目录不保存支付私钥，也不直接改订单状态。微信工程创建入口可能变化，执行时请以微信公众平台当前页面和官方文档为准。

### Codex 提示词

```text
角色：你是谨慎的 TypeScript 单仓库架构助教。
任务：只审阅或创建第10课规定的目录和 README，不实现业务功能；先列计划并等待确认。
上下文：项目含用户小程序、教练小程序、PC 后台、云函数和共享包；订单、支付、退款、核销只能由后端处理。
允许范围：apps/、cloudfunctions/、packages/ 的空目录与 README，以及根 README；仅修改明确指定路径。
禁止范围：不得实现登录、数据库、订单、支付、UI、真实配置、依赖升级、Git 发布或历史修改。
功能要求：说明每个目录职责、跨端边界、最小启动与验证方式。
安全要求：不读取或写入 AppID、云环境、密钥、证书、个人数据或生产配置；使用 <PLACEHOLDER>。
测试要求：运行目录清单、git diff --check 和已有课程审计；如无法启动如实报告。
验收要求：三端、云函数和共享包职责清楚，敏感状态仅由云函数目录承担。
报告要求：列出修改文件、验证结果、未执行原因、风险和下一步；不要自行提交或推送。
```

### 产出物

最小单仓库目录、各目录 README 和工程初始化检查记录。

### 验收标准

- [ ] 三端、云函数、共享包均有独立目录和职责说明。
- [ ] 共享包不依赖页面、数据库或凭据。
- [ ] 未实现订单、支付或生产功能。
- [ ] 无真实配置或敏感文件进入 Git。
- [ ] `node scripts/audit-course.mjs` 通过。

### 自查清单

- [ ] 我能说明新文件应放在哪个目录。
- [ ] 我没有用一个端的配置替代另一个端。
- [ ] 我先看 diff 再暂存文件。

### 提交记录

提交前运行 `git diff --check` 与 `node scripts/audit-course.mjs`；提交信息示例：`chore: scaffold project boundaries`。
