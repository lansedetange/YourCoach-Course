# 第 11 阶段：环境与 AppID 管理

### 本课目标

用一份脱敏环境清单区分开发、测试、生产，并让每个应用只读取本环境允许的配置。

### 你将完成

环境矩阵、`.env.example` 占位示例和部署文档中的配置来源说明。

### 前置条件

已完成第 10 课目录边界；知道 AppID 是应用标识，不是密码，也不能替代支付或云端密钥。

### 核心概念

- **环境**：同一系统的独立运行空间。开发用于本地试验，测试用于联调，生产服务真实用户。
- **配置注入**：运行时从受控位置读取值，而不是把真实值写进源码或 Git。
- **最小权限**：开发配置不能获得生产数据或支付权限。

### 本课范围

只写环境清单、占位符和配置规则；不创建真实云环境、不申请 AppID、不配置支付或上传证书。

### 关键决策

用户端、教练端和后台各自有 AppID/运行配置；开发、测试、生产不能共享云环境和凭据。

```text
端 × 环境 → 受控配置 → 应用读取 → 后端执行敏感操作
```

### 操作前检查

1. 打开 `docs/DEPLOYMENT.md`、`AGENTS.md` 和各端 README。
2. 确认 `.env` 已被 Git 忽略；若不确定，运行 `git status --short` 检查。
3. 只准备 `<USER_APPID_DEV>` 等占位符，不准备真实值。

### 步骤 1

在 `docs/DEPLOYMENT.md` 写环境矩阵：开发/测试/生产三行，用户端/教练端/后台/云函数四列。每格只写用途、配置来源和负责人，例如“开发云环境：仅本地受控配置”。预期结果：每项配置能回答“属于哪个端、哪个环境、谁维护”。

### 步骤 2

创建仅含名称的 `.env.example`，不填写真实值：

```text
USER_MINIPROGRAM_APPID=<USER_APPID>
COACH_MINIPROGRAM_APPID=<COACH_APPID>
ADMIN_PUBLIC_URL=<ADMIN_URL>
CLOUD_ENV_ID=<CLOUD_ENV_ID>
```

同时在 README 说明真实 `.env` 只保存在本机或受控密钥服务。预期结果：新成员知道需要哪些变量，但无法从仓库获得真实配置。

### 步骤 3

检查应用配置文件：小程序端只使用本端 AppID；后台公开变量不含密钥；云函数密钥只在云端受控配置中读取。运行：

```bash
git status --short
git diff --check
```

预期结果：没有 `.env`、证书、私钥或生产标识进入待提交列表。

### 步骤 4

为配置错误写排查顺序：先确认端、环境、变量名和配置来源，再检查是否需要重新构建/部署；绝不把生产值复制到开发环境。让 Codex 只审阅占位符和文档，运行 `node scripts/audit-course.mjs`。预期结果：错误能定位为配置问题，而不是盲改业务代码。

### 常见问题

- **一套 AppID 跑所有端**：端隔离失效，发布和权限难以管理。
- **把 `.env` 加进 Git**：会泄露凭据；立刻停止传播并轮换暴露值。
- **测试连生产云环境**：测试数据可能污染真实订单；建立独立环境。
- **前端保存支付密钥**：密钥只能由受控后端读取。

### 安全与合规

不写入真实 AppID、商户号、密钥、证书、环境 ID、个人信息或生产 URL。环境、备案、支付和发布规则可能变化，执行时请以微信公众平台当前页面和官方文档为准。

### Codex 提示词

```text
角色：你是谨慎的环境配置审阅者。
任务：只审阅环境矩阵、.env.example 和部署文档；先给最小计划。
上下文：三端和云函数隔离；订单、支付、退款、核销只由后端处理。
允许范围：docs/DEPLOYMENT.md、.env.example、指定 README。
禁止范围：不得读取、创建或输出真实配置、云环境、支付配置、证书、Git 发布。
功能要求：检查端/环境映射、变量命名和配置来源。
安全要求：所有值使用 <PLACEHOLDER>，开发环境无生产权限。
测试要求：运行 git status --short、git diff --check、node scripts/audit-course.mjs。
验收要求：仓库不含真实凭据，任何变量都有端和环境归属。
报告要求：列出改动、验证、风险和下一步；不要自行提交或推送。
```

- [ ] Git 未跟踪真实配置、证书或密钥。
- [ ] 敏感配置不由前端读取。
- [ ] 课程审计通过。
