# 课程名称：00 课程使用说明与最终成果

### 本课目标

建立零基础学习节奏、确认项目边界，并学会把每次 Codex 修改限制在可验证的小任务中。

### 你将完成

你会明确最终交付的用户端小程序、私教端小程序、PC 管理后台和云开发后端；能记录学习进度而不把任何凭据写入仓库。

### 前置条件

1. 一台可安装微信开发者工具的电脑和稳定网络。
2. 一个长期可用邮箱；密码、验证码和证件信息不能写入课程文件。
3. 已打开本课程仓库根目录。

### 核心概念

- **MVP**（最小可行产品）：第一版只验证核心预约闭环，不等于所有设想。
- **Git**：记录文件历史的工具，便于查看和回退 AI 改动。
- **三个端**：用户端用于预约，私教端用于排期和处理订单，后台用于审核运营。

### 本课范围

本课只建立学习与文档基线，不注册账号、不创建真实支付、不部署业务代码。第一版只支持同城到店、教练单时段一笔有效订单；不做上门、团课、直播、社区或复杂聊天。

### 关键决策

课程默认采用“小任务 + Git diff + 可回退版本”：先读文档，再计划，再改一个目录，最后执行检查。这样比让 AI 一次生成完整平台更容易发现错误。

```text
学习准备 → 产品文档 → 三端与云端预约闭环 → 测试 → 备案/审核/发布
用户：找教练 → 选场馆和时段 → 预约/支付 → 核销 → 评价
```

### 操作前检查

1. 打开 `README.md`、`AGENTS.md`、`docs/课程总纲.md`。
2. 确认终端当前目录是课程仓库，而不是下载目录或其他项目。
3. 运行 `git status --short`；预期是显示现有改动或没有输出，先不要删除任何已有改动。

### 步骤 1

1. 在 `docs/PRODUCT.md` 中找到项目目标模板。
2. 只填写项目名称和目标用户，不填写真实个人信息。
3. 写下第一版支持“同城、到店、选择场馆、选择时段、预约闭环”。
4. 预期结果：你能用一句话说明本项目不是通用健身社区。

### 步骤 2

1. 新建本地学习记录，例如 `learning-log.md`；若提交到 Git，只记日期、课程、结论和待办。
2. 账号项统一写占位符，如 `<USER_MINIPROGRAM_APPID>`、`<DEV_CLOUD_ENV_ID>`。
3. 不记录密码、验证码、商户私钥、证书、API 密钥、手机号或身份证信息。
4. 预期结果：学习记录可安全分享给同学。

### 步骤 3

1. 在笔记写下后续里程碑：主体与账号、云开发、工程、三端、订单、模拟支付、真实支付、测试、备案审核、发布。
2. 将真实支付、备案和审核标为“必须在官方平台人工确认”。
3. 执行时请以微信公众平台当前页面和官方文档为准。
4. 预期结果：你的学习清单把可在本地完成的任务与必须在官方后台人工确认的任务明确分开。

### 步骤 4

1. 每次向 Codex 提出一个任务，例如“补充订单状态文档”。
2. 要求它先读相关文档、给计划、只改指定目录、运行已有检查。
3. 修改后在仓库根目录运行 `git diff -- course docs`，确认无敏感内容和无关文件。
4. 预期结果：每项改动都有范围、检查结果和可回退点。

### 常见问题

- **让 AI 生成整个项目**：范围没有验收标准。拆为“一个目标、一个目录、一个检查”。
- **没有看 diff**：不知道 AI 实际做了什么。运行 `git diff -- <文件>` 逐行检查。
- **本地页面能打开就认为上线**：页面演示不代表支付、备案、审核已完成；这些必须在对应官方后台确认。

### 安全与合规

任何真实凭据都不能进入 Markdown、代码、终端输出或 Git 提交。发现泄露时停止传播、删除暴露内容，并在相应平台作废或轮换凭据。涉及账号规则、费用、审核时长或资格的信息都不是固定课程结论。执行时请以微信公众平台当前页面和官方文档为准。

### Codex 提示词

```text
角色：你是谨慎的微信小程序项目助教。
任务：审阅第 00 课的学习准备文档，只提出最小的文档改进建议。
上下文：同城健身私教预约平台包含用户端、私教端、PC 管理后台和云开发后端；MVP 仅同城到店；金额用整数分；订单、支付、退款、核销只能由后端处理。
先阅读：README.md、AGENTS.md、docs/课程总纲.md、docs/PRODUCT.md 和本课文件。
允许范围：仅 course/00-导学与学习方法/00-课程使用说明与最终成果.md 与 docs/。
禁止范围：不得创建业务代码，不得修改 apps/、cloudfunctions/、支付或生产配置、Git 历史；不得添加依赖或发布。
功能要求：核对最终成果、MVP 边界、学习顺序和回退方式。
安全要求：不得读取、输出、写入或索要密码、验证码、证书、私钥、API 密钥、真实 AppID、手机号或身份证；使用 <PLACEHOLDER>。
测试要求：只运行已有的文档审计或链接检查；命令不存在时如实报告。
验收要求：给出不超过 5 条、带文件路径的建议。
报告要求：列出已读文件、改动或建议、实际执行的检查及结果、未验证事项。
```

将提示词交给 Codex 后先审阅计划。若它改文件，运行 `git diff -- course docs`；只保留符合允许范围的改动。

### 产出物

一份安全学习记录和一段 MVP 说明。配置只能使用占位符：

```md
- 用户端 AppID：<USER_MINIPROGRAM_APPID>
- 开发云环境：<DEV_CLOUD_ENV_ID>
- 下一步：01-理解微信小程序生态
```

### 验收标准

- 能说出三个端和云端的作用。
- 已写出 MVP 支持与不支持的范围。
- 学习记录不含秘密或个人证件资料。
- 能说明 Codex 的“先读、计划、限范围、检查、报告”流程。

- [ ] 已建立仅使用占位符的学习记录。
- [ ] 已执行或理解 `git status --short` 与 `git diff` 的用途。
