# 第 28 阶段：订阅消息与通知

### 本课目标

设计合规、可恢复的订单通知：用户在清楚场景下选择订阅，后端在可信业务事件后发送最小模板信息，发送结果被记录但绝不影响订单、支付、退款或履约事实。

### 你将完成

通知事件清单、授权交互、模板字段最小化、站内通知记录、失败补偿与验收案例。

### 前置条件

- 已完成订单、支付、退款、核销和角色状态机。
- 已确认当前可用消息能力、模板配置、授权要求和平台限制由负责人在官方页面核实。
- 已有 `notifications` 集合和后端事件入口。

### 核心概念

通知是业务状态的“投递”，不是业务状态本身。订单先在后端完成状态转换和日志记录，通知作为后续、可重试的副作用；即使用户拒绝授权、模板发送失败或设备离线，订单和资金状态也不能回滚、重复或卡住。

订阅授权必须有明确上下文：例如用户确认预约后提示接收预约/服务变更提醒，而不是在页面首次打开时泛化索取。发送内容最小化，只包含必要的时间、场馆/服务摘要和安全跳转，不包含身份证、完整联系方式、支付凭据、后台审核意见或其他用户信息。

### 本课范围

本课覆盖订单类订阅消息和站内通知，不做营销群发、短信、外呼、用户画像、自动化广告或真实模板标识配置。模板、配额、类目、跳转和授权规则会变化，以当前官方文档为准。

### 关键决策

- 事件从后端订单/支付/退款/排期状态变化触发；客户端不能自行宣布“已发送”。
- 每类通知有去重键，例如订单 ID + 事件类型 + 状态版本，避免重试/回调导致重复骚扰。
- `notifications` 保存接收者、事件类型、最小安全载荷、状态、重试次数和时间；不保存完整授权原文或敏感业务数据。
- 发送失败写记录并按可控策略重试/站内提示，不影响关键状态机；用户可拒绝非必要通知。

### 操作前检查

1. 列出 MVP 必要事件：预约创建、待支付提醒、支付/确认结果、服务提醒、取消/退款结果；删除营销性质不明的事件。
2. 为每类事件确定接收者、触发状态、最小字段、跳转页、去重键和失败策略。
3. 在开发环境准备虚构订单和用户，绝不使用真实模板 ID、联系方式或授权记录。
4. 核对页面授权文案能说明“为何在此时请求、将收到什么、拒绝后有什么影响”。

### 步骤 1

设计授权交互。只在用户完成与通知直接相关的动作后请求可选订阅，例如创建预约后的服务状态提醒；拒绝授权不阻断预约、支付或查看订单。页面记录本地交互结果仅用于体验提示，后端仍以平台允许发送条件为准，不能把“曾点同意”当作永久授权。

授权前说明最小信息范围与站内替代路径；不将模板参数、内部订单 ID、用户身份标识或营销文案暴露在前端日志。官方授权 API、模板和限制可能变化，执行时请以微信公众平台当前页面和官方文档为准。

### 步骤 2

设计后端事件表。订单状态成功写入后追加通知任务：例如 `PENDING_PAYMENT`、`CONFIRMED`、`READY_FOR_CHECKIN`、`CANCELLED`、`REFUNDED`。任务先检查事件去重键、接收者和有效订单归属，再构造最小模板变量；发送结果更新 `notifications` 而非重新触发订单状态。

对教练通知同样遵循最小范围，例如新待确认订单只通知归属教练。任何模板跳转都指向需登录且后端鉴权的订单详情，不能在 URL 放置可复用凭证或敏感资料。

### 步骤 3

制定失败处理。渠道拒绝、网络错误、配额限制、模板失效或用户未订阅时记录安全错误分类，按事件重要性选择有限重试、站内通知、后台告警或停止重试。重试使用相同去重键，重复投递不重复创建通知记录；对已终态订单避免发送过期提醒。

通知中心按用户归属读取，用户可标记已读但不能修改正文、接收者或业务状态。后台仅查看必要发送统计和失败摘要，不查看用户完整授权信息或敏感模板参数。

### 步骤 4

用虚构数据验证：用户在预约后授权/拒绝两条路径；订单确认后生成一次通知；重复状态事件不重复发送；模板发送失败只写失败记录、不改变订单；通知跳转后仍需登录且只读本人订单；教练只收到本人订单提醒。检查无敏感字段进入模板或日志。

记录真实模板申请、平台审核、线上配额和送达率为上线前人工核对项。不要用测试发送成功证明生产授权或模板一定可用。

### 常见问题

- **把通知发送成功当作支付成功：** 支付/订单事实先由后端确认，通知失败不可回滚业务。
- **在首页强制请求授权：** 应在用户理解用途的上下文中选择性请求。
- **回调重试导致多条提醒：** 使用状态版本/事件去重键。
- **模板携带完整手机号或支付信息：** 仅传必要摘要，详情页再经鉴权读取。
- **失败无限重试：** 设定次数、退避、终止和人工告警策略。

### 安全与合规

通知遵循最小必要、明确场景、用户选择、最小字段与受控留存原则。订单、支付、退款与核销只由后端状态机决定，通知失败不影响它们。不得在课程、代码、日志、截图或仓库写入真实模板标识、联系方式、授权原文、凭据或生产配置。执行时请以微信公众平台当前页面和官方文档为准。

### 验收标准

- [ ] 授权在明确业务上下文中请求，拒绝不阻断核心服务。
- [ ] 通知由后端已确认状态事件触发，且有去重和最小字段。
- [ ] 发送失败不改变订单、支付、退款、排期或核销状态。
- [ ] 跳转和通知中心仅能读取接收者自身数据。
- [ ] 未使用真实模板、联系方式、凭据或生产配置。

### 自查清单

- [ ] 未把通知当作业务状态回执。
- [ ] 未在首页/无关场景泛化索取订阅。
- [ ] 重复状态事件和重试不重复创建/发送通知。
- [ ] 模板、URL、日志均无敏感字段。
- [ ] 已记录平台模板/配额的人工核对项。
