# 第 29 阶段：地图定位与附近教练

### 本课目标

设计可选、最小化的位置能力：用户可授权获取粗略当前位置以排序同城已上线服务，也可手动选城；系统只使用公开场馆位置计算附近结果，不长期保存用户精确轨迹。

### 你将完成

定位授权与降级流程、城市筛选与附近排序规则、位置数据边界和虚构数据验收案例。

### 前置条件

- 已完成场馆、教练-场馆关联和用户端浏览流程。
- MVP 范围只支持本城到店服务，场馆公开位置和城市归属已受控维护。
- 已确认地图/定位能力、Key、隐私说明和平台要求需由负责人在当前官方页面核实。

### 核心概念

“附近”是一个可选排序信号，不是用户身份、订单资格或安全证明。用户拒绝定位、定位失败或设备无权限时，仍可手动选择城市并浏览服务；后端和页面不能因此拒绝基础功能。距离应基于已公开的场馆位置，而不是教练居住地或实时用户轨迹。

定位数据属于敏感个人信息。收集前说明目的和范围；只在当前查询中使用所需精度，尽量不写入数据库和日志；如确需临时传给后端，使用最小精度、明确保留期限和访问边界，绝不用于无关画像或营销。

### 本课范围

本课只做同城场馆附近排序与手动选城，不做实时追踪、路线导航、地理围栏、位置社交、跨城服务、精确住址收集或历史轨迹分析。真实地图 Key 不写入课程或仓库。

### 关键决策

- 默认城市来自用户手动选择或设备系统信息；定位只在用户主动触发附近排序时请求。
- 后端只查询 `ACTIVE` 场馆及其有效教练关联，按城市过滤后再按距离/业务排序；距离只是展示近似值。
- 场馆精确坐标仅由受控后台维护，用户端按产品需要展示地址摘要或导航入口；不展示教练私人位置。
- 用户位置不进入长期 `users` 文档，不写日志/分析原文；失败时无缝降级为手动选城/综合排序。

### 操作前检查

1. 列出位置使用目的：找同城场馆、附近排序、导航；删除不必要的位置字段。
2. 确认隐私说明、授权文案、手动选城、关闭定位和失败提示均可访问。
3. 准备三个虚构场馆坐标/城市和一个虚构用户位置；不使用真实住址或坐标。
4. 明确查询返回公开教练/场馆摘要，不返回内部精确位置、合同、审核资料或其他用户定位。

### 步骤 1

设计授权与降级。用户点击“附近”后，页面解释会用当前位置排序同城公开服务，并提供“手动选择城市”入口；拒绝、超时、系统关闭或定位失败时，保留城市筛选和综合排序。不要在首页自动弹出强制定位，也不要将拒绝记录为用户负面标签。

授权成功后，页面只在本次查询内使用所需位置精度；需要传给后端时传递最小坐标/网格和请求 ID，后端不持久化原始位置。实际 API 字段和授权方式以当前官方文档为准。

### 步骤 2

设计查询。先用城市/服务范围过滤 `venues`、`coach_venues`、`coaches` 和 `projects` 的有效公开组合，再计算或调用受控地图服务得到距离排序；没有位置时按城市内综合排序。返回教练展示名、主项目、场馆摘要、近似距离和可约状态，不返回精确坐标、用户位置或审核字段。

距离与价格、评分、可约时段等多因素排序应可解释且可配置，避免把“最近”误导为“唯一推荐”。下单仍必须选择有效场馆和时段，位置排序不替代后端订单校验。

### 步骤 3

设计数据保留和第三方边界。地图 Key、服务端调用权限和配额只经密钥管理/环境变量注入；前端仅使用平台要求的受限配置。位置请求日志仅保留必要的错误分类、城市/粗粒度统计和请求 ID，定期删除或聚合；不记录精确经纬度、设备标识或完整地址。

当地图服务不可用、配额耗尽或返回异常时，页面切换至城市列表/文本地址而非阻塞预约。后台修改场馆位置需审计，防止错误或恶意位置影响附近排序。

### 步骤 4

用虚构数据验证：用户授权后看到同城公开场馆的附近排序；拒绝定位后仍能手动选城；定位失败/地图异常后正常降级；不同城市结果不混入；下架场馆和失效关联不出现；请求/日志不保存精确用户位置。检查详情和预约仍重新验证场馆、时段和订单状态。

记录未验证项：真实地图 Key 配置、生产配额、导航能力、隐私审批和平台审核。不要用开发环境虚构坐标证明真实地图服务已可用。

### 常见问题

- **拒绝定位就不能预约：** 定位是可选排序，必须提供手动选城。
- **把用户坐标存进用户档案：** 当前功能不需要长期保存，避免收集。
- **附近结果显示下架场馆：** 查询先过滤公开有效状态和关联。
- **展示教练实时位置：** 只使用公开服务场馆位置，保护个人安全。
- **地图失败导致空白页：** 回退到城市筛选/文本地址。

### 安全与合规

位置数据按最小必要、明确目的、用户选择、最短保留、最小访问和安全传输处理。地图 Key、真实坐标、住址、设备标识和生产配置不进入课程、日志、截图或版本库。定位不影响订单/支付事实，订单仍由后端状态机校验。执行时请以微信公众平台当前页面和官方文档为准。
