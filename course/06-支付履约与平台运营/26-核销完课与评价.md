# 第 26 阶段：核销、完课与评价

### 本课目标

设计到店核销、服务进行、完课和评价的可信顺序，确保核销只由有权角色在正确订单状态下执行，评价只来自实际完成服务的订单。

### 你将完成

核销凭证与状态规则、完课确认流程、评价资格/展示/审核边界、争议与重复操作的验证清单。

### 前置条件

- 已完成已支付订单、排期锁定、取消退款和订单状态机课程。
- 已明确核销人、服务地点和服务时间窗口。
- 已有 `checkin.verify`、`order.transition`、`review.create` 的受控接口约定。

### 核心概念

核销证明“服务开始或用户到店”，不是“服务已经完成”。合法链路为 `READY_FOR_CHECKIN → IN_PROGRESS → COMPLETED`：核销仅将订单置为进行中；在服务完成、无退款/异常阻断且符合角色规则后，后端才可完课；仅 `COMPLETED` 订单的真实用户可创建一次评价。

核销凭证（二维码、短码或人工确认）是候选输入，不是权限本身。服务端必须校验订单状态、教练/管理员归属、时段窗口、凭证有效性和幂等键；凭证不可在日志、截图或页面长时间明文保存。

### 本课范围

本课设计 MVP 核销、完课和评价，不实现人脸识别、地理围栏、双向评价、复杂内容审核、申诉仲裁或自动反作弊。争议、投诉和监管要求进入受控人工流程。

### 关键决策

- 核销凭证短时有效、一次性/可验证、与订单绑定；不以静态可猜字符串替代服务端校验。
- 教练只能核销自己的、处于合法窗口的订单；管理员核销需更高权限和原因审计。
- 完课由受控角色/规则执行，不能由用户或教练页面任意跳过状态。
- `reviews` 以 `order_id` 唯一，内容先经最小校验和审核状态控制；公开列表只读已发布内容。

### 操作前检查

1. 阅读订单状态机，确认核销前、核销后、完课、退款/取消状态的合法动作。
2. 准备虚构的待核销订单、已核销订单、已退款订单和非本人订单。
3. 定义凭证的有效期、显示范围、失效条件和服务端存储方式，不使用真实用户信息。
4. 明确评价字段最小化：评分、可选文本、订单/教练引用和审核状态。

### 步骤 1

设计核销入口。用户端在服务窗口展示短时凭证或请求核销意图；教练端扫描/输入后调用 `checkin.verify`，后端从可信教练身份读取订单，确认订单为 `READY_FOR_CHECKIN`、教练归属、时段窗口和凭证都有效，再转换为 `IN_PROGRESS` 并追加订单日志。

核销成功页面只显示必要状态和时间，不回显可复用凭证。重复扫描返回同一核销结果或稳定状态冲突；越权、过早、已退款、已取消订单均拒绝且不改变任何资金/排期记录。

### 步骤 2

设计完课。教练完成服务后发起具名完课动作，后端校验订单已核销、教练归属、服务时间与无退款阻断，再由 `IN_PROGRESS` 转为 `COMPLETED`。需要用户确认、延迟确认或异常申报时，以产品配置/人工流程实现，不能让前端绕过状态机。

完课事件是收益结算和评价资格的前置条件，必须写入不可变 `order_logs`。若服务未完成、用户未到店或发生争议，记录受控异常分类，停留在可处理状态，不伪造完课。

### 步骤 3

设计评价。`review.create` 从可信用户身份确认订单归属、状态为 `COMPLETED`、尚无该订单评价，校验评分范围和文本长度后创建 `reviews`，初始为受控审核/发布状态。用户只能修改/删除自己在允许窗口内的评价；教练不能代用户创建评价，管理员审核/隐藏要写审计。

公开教练详情只显示已发布、已脱敏的评价内容与聚合摘要。举报、争议、侵权或不当内容进入人工审核，不在客户端暴露审核人、举报人或内部原因。

### 步骤 4

用虚构数据验证：合法核销成功并进入 `IN_PROGRESS`；重复核销不重复写日志；非本人/已退款/过早核销被拒绝；合法完课进入 `COMPLETED`；同一用户创建一次评价成功、第二次拒绝；未完课或他人订单评价被拒绝。逐项检查状态、日志和评价唯一性。

记录未验证项，如真实扫码硬件、内容审核服务和争议处理 SLA。平台凭证、内容治理和隐私要求变化时，执行时请以微信公众平台当前页面和官方文档为准。

### 常见问题

- **核销即完课：** 核销表示开始服务，完课需独立状态与证据。
- **二维码/短码永久有效：** 凭证需绑定订单、短时有效且由后端验证。
- **评价只靠页面隐藏按钮：** 后端验证订单归属、完课状态和一次性约束。
- **教练删除差评：** 只能走受控审核/举报流程并保留审计。
- **已退款订单仍可核销/评价：** 状态机必须拒绝。

### 安全与合规

核销、完课、评价资格和展示状态均由后端鉴权、状态和幂等规则决定。凭证、行程、评价文本、用户资料和审核信息最小化展示和记录；不得写入真实凭据、个人数据、订单或生产配置。执行时请以微信公众平台当前页面和官方文档为准。

### 验收标准

- [ ] 核销、完课、评价依次受状态机约束，核销不等于完课。
- [ ] 核销校验订单归属、状态、窗口、凭证和幂等，越权无副作用。
- [ ] 只有订单用户可对 `COMPLETED` 订单评价一次。
- [ ] 评价公开内容受审核状态控制，内部审核信息不泄露。
- [ ] 未使用真实凭证、用户数据、交易或生产配置。

### 自查清单

- [ ] 未采用永久明文核销码或客户端判定。

- [ ] 所有履约状态变更写入订单日志。
- [ ] 评价唯一性由后端/数据库共同保证。
- [ ] 已检查日志、样例和 git diff 脱敏。
