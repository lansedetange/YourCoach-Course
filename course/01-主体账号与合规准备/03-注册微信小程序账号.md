# 课程名称：03 注册微信小程序账号

### 本课目标

在不泄露账号资料的前提下，理解小程序注册、主体信息、管理员、认证、AppID 与多端规划的操作顺序。

### 你将完成

你能在官方平台按照当前页面完成或准备小程序注册；能安全记录用户端与私教端的 AppID 占位符，并知道认证、备案、支付不是注册动作的自动结果。

### 前置条件

1. 已完成第 02 课，主体负责人已确认可用于注册的材料与管理员安排。
2. 有一个未被占用且可长期接收邮件的工作邮箱；不要把邮箱密码或验证码交给任何人或 AI。
3. 已获得主体负责人许可，且由有权人员完成需要身份确认的操作。

### 核心概念

- **注册邮箱**：用于登录、验证和通知的邮箱，应由组织可持续管理。
- **管理员**：在平台中拥有管理权限的人员，应最小化授权并可追溯。
- **主体信息**：注册时关联的登记主体资料，必须与实际材料一致。
- **认证**：平台对主体或能力的验证流程；与创建账号不同，具体规则需官方核验。
- **AppID**：小程序身份标识，后续创建项目和关联能力时使用。

### 本课范围

本课只注册或完成注册准备，不上传开发代码、不配置支付、不创建云环境、不假设认证或备案已经通过。用户端和私教端是否使用两个 AppID，课程默认按两个独立端规划；实际架构由产品和审核要求再确认。

### 关键决策

使用组织可管理的邮箱和明确的管理员角色，避免账户绑在离职人员私人邮箱或个人手机上。一个应用身份对应一个小程序版本与权限边界；不要为了省事混用用户端和私教端身份。

```text
主体授权与邮箱准备 → 官方平台注册 → 选择小程序与主体 → 管理员验证
→ 记录 AppID（仅安全位置） → 后续认证/开发/备案分别处理
```

### 操作前检查

1. 再确认当前浏览器地址属于微信官方站点，避免从搜索广告或陌生链接输入资料。
2. 确认电脑没有屏幕共享或录屏；验证码不应展示给他人。
3. 在安全记录中预先写好 `<USER_MINIPROGRAM_APPID>` 和 `<COACH_MINIPROGRAM_APPID>`，不要用真实值占位。
4. 执行时请以微信公众平台当前页面和官方文档为准。

### 步骤 1

1. 使用浏览器进入微信公众平台的当前官方注册入口。
2. 在页面选择与当前目标相符的“小程序”注册类型；如页面名称变化，以当前说明为准。
3. 填写由组织管理的注册邮箱，完成该邮箱的验证步骤。
4. 预期结果：平台进入账号或主体资料填写流程；不要在课程仓库记录验证内容。

### 步骤 2

1. 按当前页面要求选择已确认的主体类型，由有权人员填写真实主体资料。
2. 确保资料与合法材料一致；遇到不理解字段，暂停并向主体负责人或官方支持确认。
3. 不在截图、终端、Codex 对话或 Markdown 中复制主体号码、姓名、联系方式和证件图片。
4. 预期结果：平台显示待完成、审核中或已完成等真实状态；只记录状态，不编造结果。

### 步骤 3

1. 按平台当前要求指定管理员并完成管理员验证。
2. 只授予完成当前任务所需权限；不要多人共享同一个登录密码。
3. 在内部状态表记为 `<ADMIN_SETUP_STATUS>`，不要保存真实管理员身份信息。
4. 预期结果：组织能确认谁负责后续成员、版本和安全设置。

### 步骤 4

1. 注册完成后在平台当前的开发或基本信息页面查找 AppID。
2. 将用户端记为 `<USER_MINIPROGRAM_APPID>`，私教端另行按同样原则规划 `<COACH_MINIPROGRAM_APPID>`。
3. 只在受控的配置管理位置保存真实值；课程仓库始终保留占位符。
4. 记录“认证、备案、支付：待后续课程逐项核验”。
5. 预期结果：你能区分账号已注册和能力已开通。

### 常见问题

- **邮箱已被占用**：不要反复猜密码；确认该邮箱是否已有账号，或使用组织批准的另一个长期邮箱。
- **主体字段不确定**：不要随意填写或借用他人资料；暂停并请主体负责人核验。
- **找不到 AppID**：先确认账号注册状态和当前权限，再根据平台当前“开发/基本信息”说明查找。
- **认为注册后已能收款**：支付、认证、备案和类目仍需分别确认。

### 安全与合规

邮箱密码、验证码、主体资料、管理员身份、AppID 关联配置、支付资料和证书均不应进入公开仓库。管理员离职、权限变化或疑似泄露时，应由组织按平台当前流程更换授权或轮换凭据。执行时请以微信公众平台当前页面和官方文档为准。

- 能解释注册、认证、备案和支付不是同一个步骤。
- 已完成用户端与私教端 AppID 的独立规划。
