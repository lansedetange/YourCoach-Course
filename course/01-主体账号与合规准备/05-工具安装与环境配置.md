# 第 5 阶段：工具安装与环境配置

### 本课目标

在不创建业务代码、不使用真实生产凭据的前提下，准备一台可以管理课程仓库、运行基础命令、打开微信小程序练习项目并使用 Codex 审阅改动的电脑。

### 你将完成

1. 一份仅记录工具版本和检查结果的本机环境检查记录。
2. Git、Node.js、微信开发者工具和 Codex 的可验证安装状态。
3. 一个只用于验证工具的本地小程序练习项目；它不是最终业务项目，也不连接支付或生产云环境。

### 前置条件

1. 已完成第 04 课，理解开发、测试、生产环境必须分开。
2. 有一台可自行安装软件的 macOS 或 Windows 电脑，并能使用浏览器下载官方安装包。
3. 已有一个微信账号和一个 GitHub 账号；本课不要求输入密码、验证码、AppID、商户号或任何密钥。
4. 已将课程仓库下载到本机，并能在文件管理器中找到它。

### 核心概念

- **终端**：输入命令并查看结果的窗口；macOS 常见为“终端”，Windows 可使用 PowerShell。
- **Node.js**：运行 JavaScript 工具的运行时。本课只用它检查版本和运行课程审计脚本，不用它编写小程序页面。
- **Git**：记录文件变更历史的工具；`git diff` 可以让你检查 AI 实际改了什么。
- **微信开发者工具**：编辑、预览、调试和上传微信小程序的官方桌面工具。
- **练习项目**：只用来确认工具可打开项目的本地目录，不是最终用户端或私教端工程。

### 本课范围

本课只准备工具和记录验证结果。不要创建 `apps/`、`cloudfunctions/` 中的业务代码；不要创建真实云环境、支付配置、数据库集合或生产项目。第 10 课才会创建正式项目工程。

### 关键决策

课程默认使用官方安装包与工具自身的版本检查，而不是要求初学者通过第三方脚本安装。这样故障来源更少，也避免把本机凭据或代理配置复制进仓库。

```text
电脑与账号准备
        ↓
Git + Node.js 版本检查
        ↓
微信开发者工具打开练习项目
        ↓
Codex 阅读文档、给计划、修改后查看 git diff
        ↓
写入脱敏环境检查记录
```

### 操作前检查

1. 打开课程仓库根目录，确认能看到 `README.md`、`AGENTS.md` 和 `course/`。
2. 准备一个只用于练习的本地目录，例如“文档/yourcoach-practice”；不要把它放在网盘同步、U 盘或包含敏感文件的目录中。
3. 准备一份空白笔记，标题可写为“环境检查记录”；只记录工具名称、版本、日期和“通过/失败”。
4. 确认没有把密码管理器、聊天记录、证件照片、支付证书或密钥文件拖入课程仓库。

### 步骤 1

安装并验证 Git 与 Node.js。

1. 在浏览器分别访问 Git 和 Node.js 的官方下载安装页面，选择与你电脑系统匹配的稳定版本安装包。不要从不明镜像站下载。
2. 安装完成后，打开终端。macOS 可打开“终端”；Windows 可打开 PowerShell。
3. 输入以下命令；每一行输入后按回车。命令在终端执行，不是在微信开发者工具或 Codex 对话框执行。

```bash
git --version
node --version
npm --version
```

4. 预期结果：每条命令都输出版本号，例如以 `git version`、`v` 或数字开头；不要把版本号之外的个人路径或账号信息贴到公开讨论区。
5. 若提示“找不到命令”，先关闭所有终端窗口，重新打开一个终端再试；仍失败时，重新运行官方安装包并确认它已完成安装。不要复制网上的管理员权限修复脚本。

### 步骤 2

配置 Git 的本地身份并检查课程仓库。

1. 在终端进入课程仓库。macOS 或 Windows PowerShell 都可以使用以下命令，其中路径要替换为你的实际课程目录。

```bash
cd <课程仓库绝对路径>
git status --short
```

2. 预期结果：终端没有报“不是 git 仓库”；若没有未提交改动，第二行通常没有输出。
3. 若这是你第一次使用 Git，在终端为自己的电脑设置提交署名。显示名和邮箱会进入本机 Git 配置，可能出现在以后提交的作者信息中；不要把该命令输出粘贴到课程文档。

```bash
git config --global user.name "你的显示名"
git config --global user.email "你的Git提交邮箱"
```

4. 使用下列命令只确认配置存在；屏幕上会显示你刚填写的值，因此请勿截图或上传到公开仓库。

```bash
git config --global --get user.name
git config --global --get user.email
```

5. 在课程仓库运行 `git diff`。预期结果：新仓库或没有改动时没有输出；以后让 Codex 改文件后，这就是你检查改动范围的第一道门。

### 步骤 3

安装微信开发者工具并用本地练习项目验证启动。

1. 在浏览器搜索“微信开发者工具 官方”，进入微信官方开发者文档或下载页，下载与你系统匹配的安装包并完成安装。
2. 启动工具后，使用其当前版本提供的“导入项目”或“新建小程序项目”入口，选择步骤 1 准备的本地练习目录。不要选择生产项目目录。
3. 在 AppID 输入区域，使用工具当前版本提供的安全测试方式或课程后续申请的测试配置；不要填入正式用户端、私教端或支付关联的 AppID。
4. 选择最小模板或空白模板，只验证工具能创建并打开本地练习项目。不要添加页面、云函数、支付逻辑或第三方依赖。
5. 点击编译或预览区域的默认操作，观察模拟器是否显示模板页面或工具默认提示。
6. 预期结果：项目能在工具中打开，且控制台没有因为缺少 AppID、密钥或云环境而引入生产配置。

不同版本的入口、按钮名称和测试方式可能调整。执行时请以微信公众平台当前页面和官方文档为准。

### 步骤 4

配置 Codex 的最小使用习惯，并写环境检查记录。

1. 按 Codex 当前官方指引安装或打开你已可使用的 Codex 客户端；登录过程只在官方界面完成，不要把登录信息复制到终端、提示词或仓库。
2. 让 Codex 打开课程仓库后，先发送“请先阅读 `AGENTS.md`、`README.md` 和本课文件，只给出工具检查计划，不修改文件”。
3. 若 Codex 建议改文件，先要求它列出允许修改的路径和验证命令；只接受本课范围内的建议。
4. 修改发生后，在课程仓库终端运行：

```bash
git diff -- course docs
node scripts/audit-course.mjs
```

5. 预期结果：`git diff` 只显示你允许的文档改动；审计脚本输出课程审计通过。若命令失败，不要让 AI 盲目重试，先复制完整报错并要求它分析原因。
6. 在自己的本地笔记中使用如下格式记录检查结果；尖括号内容由你填写，但不要把真实 AppID、账号、路径、邮箱或密钥写入仓库。

```markdown
# 环境检查记录

- 检查日期：<YYYY-MM-DD>
- Git：<通过/失败>，版本已在本机确认
- Node.js 与 npm：<通过/失败>，版本已在本机确认
- 微信开发者工具：<通过/失败>，已打开本地练习项目
- Codex：<通过/失败>，已阅读项目文档并给出计划
- 未通过项与下一步：<仅描述故障现象，不写凭据>
```

Codex 可用于理解代码库、构建、测试和审阅改动；本课采用“先读文档、先计划、再检查 diff”的用法，以便初学者始终掌握修改范围。[OpenAI Codex 官方开发者资源](https://developers.openai.com/)

### 常见问题

- **`node` 或 `git` 找不到**：通常是安装未完成或终端仍是安装前打开的旧窗口。关闭后重开终端；确认官方安装程序已成功结束。
- **`cd` 后提示不是 Git 仓库**：进入了下载文件夹、练习项目目录或上一级目录。用文件管理器复制课程仓库的完整路径，再执行 `cd`。
- **微信开发者工具不能打开项目**：先确认你选择的是本地练习目录，且没有把正式 AppID、云环境或受限项目配置带入。查看工具控制台最早的一条错误，再按当前官方文档核对。
- **Codex 一次建议生成整个平台**：这是范围过大。改为一次只做“检查工具状态”“补一份文档”或“分析一条报错”，并要求先给计划。
- **审计脚本报错**：在课程仓库根目录运行命令，先阅读报出的文件路径和栏目名称；只修复第一条明确错误后再运行一次。

### 安全与合规

真实 AppID、商户号、API 密钥、API v3 密钥、证书、私钥、验证码、身份证件、手机号和生产环境 ID 都不应出现在本课命令、截图、提示词、日志或 Git 提交中。示例统一使用 `<PLACEHOLDER>`。

安装工具不等于取得上线、支付、备案或审核资格。不得为“让页面跑起来”而关闭权限控制、使用他人账号、共享证书或把敏感状态改到前端。执行时请以微信公众平台当前页面和官方文档为准。

### 验收标准

- [ ] `git --version`、`node --version` 和 `npm --version` 均在本机终端输出版本信息。
- [ ] 能在课程仓库根目录运行 `git status --short`，且理解没有输出代表没有待提交改动。
- [ ] 微信开发者工具能打开本地练习项目，未使用正式 AppID 或生产云环境。
- [ ] Codex 已先阅读项目文档、给出计划；任何修改后都查看过 `git diff`。
- [ ] 环境检查记录中没有账号、密码、验证码、密钥、证书、个人信息或真实生产标识。

### 自查清单

- [ ] 我把练习项目和未来正式业务项目放在不同目录。

### 提交记录

预期结果：第一条命令无输出，第二条命令显示课程审计通过。真实凭据、练习项目临时文件和本机配置不应提交。
