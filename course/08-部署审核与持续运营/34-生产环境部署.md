# 第 34 阶段：生产环境部署

### 本课目标

建立生产部署运行手册：环境隔离、版本冻结、配置/密钥注入、集合/索引迁移、云函数发布、健康检查、监控、备份和可执行回滚；不在课程中实际执行未授权生产操作。

### 你将完成

生产部署清单、发布顺序、验证/监控指标、回滚条件和负责人分工。

### 前置条件

- 自动化、联调、体验版、隐私和安全检查均通过，阻断/高缺陷关闭。
- 已有测试与生产环境隔离、最小生产权限和变更审批负责人。
- 主体、支付、备案/审核等生产前置由业务负责人另行核实。

### 核心概念

生产部署是一次受控变更，不是把开发配置复制过去。代码、云函数、数据库集合/索引、环境变量、前端版本、支付回调、监控和回滚都必须有版本、负责人、验证和恢复路径。任何不可逆数据操作应先备份、演练和审批。

回滚优先恢复服务而不是删除数据：前端/函数版本可回退，数据库迁移采用向后兼容、可读旧数据的策略；已产生的订单、支付、退款和流水不能用“回滚数据库”抹掉，必须通过受控补偿和审计处理。

### 本课范围

本课编写运行手册和演练，不创建生产环境、不输入真实密钥、不执行发布、支付、数据导入或删除。具体控制台入口、配额、发布审核和权限能力以当前官方页面为准。

### 关键决策

- 开发/测试/生产环境、数据、密钥、日志和成员严格分离，生产凭据只由受控密钥管理注入。
- 发布包与云函数使用可追溯版本/提交；配置变更与代码变更分开审查并有双人复核。
- 迁移先新增兼容字段/索引，再切换读写，最后在确认期后清理；不直接破坏旧订单/账务字段。
- 监控涵盖错误率、云函数失败、订单创建冲突、支付/退款未决、通知失败、延迟与异常权限；触发阈值有值班负责人。

### 操作前检查

1. 冻结发布候选提交，确认所有测试命令、课程审计、依赖检查和体验版证据通过。
2. 对照 `docs/DEPLOYMENT.md` 和 `docs/RELEASE_CHECKLIST.md` 列出环境、版本、配置键名、迁移、负责人和回滚负责人；只记录占位符。
3. 备份/导出策略经授权演练，确认恢复权限、保留期限和敏感数据访问边界。
4. 检查生产无调试开关、模拟支付、测试管理员、宽松数据库规则或开发回调地址。

### 步骤 1

准备发布包。锁定前端、后台、云函数和数据库模型版本，生成变更摘要与风险清单；核对生产环境的非秘密配置键存在、密钥由受控系统注入且无值显示；确认支付/通知/地图等生产能力未在未审批状态启用。

为迁移写兼容计划：新增集合/索引、先双读/兼容写、验证数据完整性、观察期、后续清理。订单、支付、退款、钱包和审计集合禁止无备份的结构性删除或批量手改。

### 步骤 2

按低风险顺序发布：数据库兼容变更与索引→云函数/后端→后台→小程序/前端版本；每一步执行健康检查并记录版本。健康检查包括登录、公开列表、创建模拟订单（如生产禁止则只读/健康检查）、云函数错误、权限拒绝、监控接入和日志脱敏。

发布中出现支付、权限、订单、数据完整性、严重错误率或性能异常时停止下一步，不在压力下跳过检查。实际发布工具和版本审核入口变化时，执行时请以微信公众平台当前页面和官方文档为准。

### 步骤 3

建立监控与值班。上线后观察错误率、接口延迟、订单状态滞留、支付/退款未决、时段冲突、通知失败、权限拒绝激增和资源配额；关联请求 ID 与版本。报警内容脱敏，运行手册列出谁接收、何时升级、何时暂停新订单/支付入口。

生产日志保留和访问遵循最小权限；不在监控中展示密钥、完整个人资料、支付回调原文或精确位置。定期演练备份恢复和密钥轮换，不等事故发生再验证。

### 步骤 4

定义回滚：前端/云函数出错回退到上一已验证版本；配置错误回滚受控配置；数据库变更使用兼容开关/补偿脚本而非删除生产订单。触发条件包括严重权限越权、资金状态错误、数据损坏、关键路径不可用、错误率阈值超标或安全事件。

回滚后验证登录、订单只读状态、支付/退款未决处理、日志与监控，记录时间线、影响、负责人和后续修复。未经授权不执行任何生产回滚或备份恢复。

### 常见问题

- **开发/生产共用密钥和数据：** 一旦泄露或误操作影响扩大，必须隔离。
- **先改生产数据库再想回滚：** 迁移要兼容、备份、演练和审批。
- **只发布小程序不发布后端：** 契约漂移会导致状态/权限错误，应按依赖顺序发布。
- **回滚直接删除订单：** 交易和审计数据需受控补偿，不能抹除。
- **监控只看服务器在线：** 还要看资金、状态、权限和业务错误。

### 安全与合规

生产变更采用最小权限、双人复核、可追溯版本、受控密钥、最小日志和审批；真实凭据、个人资料、交易、备份内容和生产配置不进入课程、代码、日志或版本库。执行时请以微信公众平台当前页面和官方文档为准。

```text
角色：你是资深 SRE、微信云开发发布与交易系统运维工程师，严格遵守项目根目录 AGENTS.md。

任务：完善生产部署运行手册，定义环境隔离、迁移、发布、健康检查、监控、备份和回滚；不执行生产操作。

上下文：YourCoach 有订单、支付、退款、钱包和多端应用，生产数据和凭据高度敏感；测试/体验版已完成。

允许范围：仅修改部署/发布文档、课程和必要的发布检查脚本；使用占位符和脱敏示例。

禁止范围：不得创建或修改生产环境、写入凭据、执行数据导入/删除/回滚、跳过审批或重构无关应用代码。

功能要求：版本冻结、配置键检查、兼容迁移、发布顺序、健康检查、业务监控、备份恢复、回滚触发/步骤/验证和负责人。

安全要求：环境/密钥/成员隔离，最小权限和双人复核，账务数据不可破坏回滚，日志脱敏，安全事件可升级。

测试要求：在测试环境演练迁移/发布/回滚清单，验证健康检查和告警路径；记录未执行生产项与原因。

验收要求：每个生产变更有负责人、证据、停止条件和恢复路径；无真实凭据/数据；上线不依赖不可验证假设。

报告要求：列出修改文件、发布决策、演练结果、未执行生产操作、风险和下一步；附 git diff 摘要，不要自行提交。
```

### 产出物

- 生产部署、监控、回滚运行手册。
- 兼容迁移与业务健康检查清单。
- 上线停止条件、负责人和演练记录。

### 验收标准

- [ ] 开发/测试/生产环境、数据、密钥和成员已明确隔离。
- [ ] 发布顺序、版本、迁移、健康检查、监控和负责人可追溯。
- [ ] 订单/资金数据有兼容迁移、备份、补偿和非破坏性回滚策略。
- [ ] 高风险错误、权限、资金、数据完整性触发停止/回滚并可验证。
- [ ] 未执行或泄露任何真实生产配置、凭据或数据。

### 自查清单

- [ ] 未把生产发布当作测试环境的复制。
- [ ] 未启用模拟支付、调试/宽松权限或测试成员。
- [ ] 每个配置只记录键名/占位符，不记录值。
- [ ] 回滚后有业务和监控验证，不只看部署成功。
- [ ] 已标记需人工核实的平台/审批步骤。
